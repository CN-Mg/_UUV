# 2.4 显控仿真软件总方案设计

交付的 PPTX 包含四页原生可编辑技术图，不另设封面。正文依据原始技术要求 2.4，以及本项目当前的场景、调度、适配器、事件与显控实现。既有 `方案图.pptx` 和技术要求 DOCX 保持不变。

## 页面内容

1. **软件总体架构**：场景想定与显控、后端计算权威、事件记录与分发。JSONL 是运行事实，SQLite 只保存场景和运行索引。
2. **参数级等效链路与真值隔离**：观测按模式直接正向投影，增量由光路差值定义。真值用于观测生成、独立评价与显控，不进入定位器。定位器接收白名单标定、最终角点与历史估计。M1 评价三种视觉方法，融合对照评价作为后续能力预留。
3. **算法接入与协作边界**：2.1 返回布局与评价，2.2 返回视觉位置与时间，2.3 返回融合契约对象。M1 明确显示固定布局、模型知情校正和 NoOp 透传状态。
4. **课题指标与实施安排**：将 2.4 的配置、多源接入、动态显示与回放、参数级链路与导出四项指标映射到当前功能、本轮完善和后续工作。

## 风格与可编辑性

参考原方案图的 16:9 画布、白底蓝标题、彩色实心模块、同色虚线分组及正交箭头。配色沿用蓝 `4F81BD`、紫 `8064A2`、红 `C0504D`、绿 `9BBB59`。标题和正文采用源文件中存在的微软雅黑、黑体。图中的模块和连接线为原生幻灯片对象，指标映射为原生表格。

源文件通过只读 PowerPoint 导出预览并逐页检查，导出图位于 `docs/design-preview/reference/`。最终设计通过 PowerPoint 逐页导出并检查，预览为 `docs/design-preview/slide-1.png` 至 `slide-4.png`。正式检查覆盖四页画布、文件结构、参考字体、重新导入和原生表格，最终无结构错误或版式警告。结构检查结果保存在私有 `.codex-design-build/`，不替代逐页视觉检查。

## 科学与实现边界

- 所有默认参数及结果为 `DEMO_UNCALIBRATED`。
- `Δ平面=平面投影−理想投影`，`Δ波面=波纹投影−平面投影`，不将折射画成任意经验像素噪声。
- 解析角点和预先已知关联不代表真实图像识别能力。
- 固定布局不算自动优化，NoOp 透传不算多传感器融合。
- 当前误差样本针对无校正、平面校正和简单平滑三种视觉方法；NoOpFusion 未独立产生融合对照评价。
- 当前圆轨迹的速度由半径与周期推导，任意航迹和阵型编辑列为后续。
- 后端同源波面采样显示属于本轮接入，最终状态以实际代码和交付记录为准。

构建入口为 `tools/build_software_design.mjs`，使用 Codex bundled `@oai/artifact-tool` 创建和验证可编辑 PPTX。原始文件不作为输出路径。
